📋 SQL Developer 64-bit Connectivity Setup

Step-by-Step Connection Configuration

1

Download & Install SQL Developer 64-bit:
Visit oracle.com, download SQL Developer for Windows 64-bit. Extract the ZIP file to a desired location (e.g., C:\sqldeveloper).

2

Launch SQL Developer:
Navigate to the installation folder and run sqldeveloper.exe. First launch may take 2-3 minutes to initialize.

3

Create New Database Connection:
In the left panel, right-click on "Connections" → Select "New Connection"

4

Fill Connection Details:

Connection Name: MyConnection (or any name) Username: SYSTEM Password: (your database password) Hostname: localhost Port: 1521 SID: xe (or orcl, depending on installation)
5

Test Connection:
Click "Test" button. You should see "Success" message. If failed, verify Oracle Database service is running.

6

Save Connection:
Click "Save" and "Connect" to establish the connection.

7

Open SQL Worksheet:
Once connected, right-click on your connection and select "Open SQL Worksheet" to start writing queries.

ℹ️ Note: If you don't have Oracle Database installed locally, you can use Oracle Database Free (XE) which is available for download on Oracle's official website.

Query 1: Simple SELECT with WHERE Clause
-- Display all employees from IT department with salary > 50000 SELECT EMP_ID, EMP_NAME, DEPARTMENT, SALARY FROM EMPLOYEES WHERE DEPARTMENT = 'IT' AND SALARY > 50000;
Output: EMP_ID | EMP_NAME | DEPARTMENT | SALARY -------|---------------|------------|-------- 103 | Amit Patel | IT | 55000 105 | Vikram Desai | IT | 52000
Query 2: Aggregate Functions
-- Calculate total, average, minimum, and maximum salary SELECT COUNT(*) AS TOTAL_EMPLOYEES, SUM(SALARY) AS TOTAL_SALARY, AVG(SALARY) AS AVERAGE_SALARY, MAX(SALARY) AS HIGHEST_SALARY, MIN(SALARY) AS LOWEST_SALARY FROM EMPLOYEES;
Output: TOTAL_EMPLOYEES | TOTAL_SALARY | AVERAGE_SALARY | HIGHEST_SALARY | LOWEST_SALARY 5 | 250000 | 50000 | 55000 | 45000
Query 3: GROUP BY and HAVING
-- Calculate average salary by department SELECT DEPARTMENT, COUNT(*) AS EMP_COUNT, AVG(SALARY) AS AVG_SALARY FROM EMPLOYEES GROUP BY DEPARTMENT HAVING AVG(SALARY) > 48000 ORDER BY AVG_SALARY DESC;
Output: DEPARTMENT | EMP_COUNT | AVG_SALARY -----------|-----------|---------- IT | 3 | 52333.33 Finance | 1 | 48000 HR | 1 | 45000
Query 4: INNER JOIN
-- Display employees and their assigned projects SELECT e.EMP_ID, e.EMP_NAME, p.PROJECT_NAME, p.BUDGET FROM EMPLOYEES e INNER JOIN PROJECTS p ON e.EMP_ID = p.EMP_ID ORDER BY e.EMP_NAME;
Output: EMP_ID | EMP_NAME | PROJECT_NAME | BUDGET -------|---------------|-------------------|-------- 103 | Amit Patel | Mobile App Dev | 300000 101 | Rajesh Kumar | E-Commerce Portal | 500000 105 | Vikram Desai | Data Analytics | 250000 102 | Priya Singh | HR Management | 150000
Query 5: LEFT OUTER JOIN
-- Display all employees with their projects (if assigned) SELECT e.EMP_ID, e.EMP_NAME, e.DEPARTMENT, NVL(p.PROJECT_NAME, 'Not Assigned') AS PROJECT_NAME FROM EMPLOYEES e LEFT OUTER JOIN PROJECTS p ON e.EMP_ID = p.EMP_ID ORDER BY e.EMP_ID;
Output: EMP_ID | EMP_NAME | DEPARTMENT | PROJECT_NAME -------|---------------|------------|-------------------- 101 | Rajesh Kumar | IT | E-Commerce Portal 102 | Priya Singh | HR | HR Management 103 | Amit Patel | IT | Mobile App Dev 104 | Neha Sharma | Finance | Not Assigned 105 | Vikram Desai | IT | Data Analytics
Query 6: Subquery (Inner Query)
-- Find employees earning more than average salary SELECT EMP_ID, EMP_NAME, SALARY FROM EMPLOYEES WHERE SALARY > (SELECT AVG(SALARY) FROM EMPLOYEES) ORDER BY SALARY DESC;
Output: EMP_ID | EMP_NAME | SALARY -------|---------------|-------- 103 | Amit Patel | 55000 105 | Vikram Desai | 52000 101 | Rajesh Kumar | 50000
Query 7: Subquery with IN Operator
-- Find employees who manage projects with budget > 300000 SELECT EMP_ID, EMP_NAME, DEPARTMENT, SALARY FROM EMPLOYEES WHERE EMP_ID IN ( SELECT EMP_ID FROM PROJECTS WHERE BUDGET > 300000 );
Output: EMP_ID | EMP_NAME | DEPARTMENT | SALARY -------|---------------|------------|-------- 101 | Rajesh Kumar | IT | 50000 103 | Amit Patel | IT | 55000
Query 8: Correlated Subquery
-- Find employees earning more than average of their department SELECT EMP_ID, EMP_NAME, DEPARTMENT, SALARY FROM EMPLOYEES e WHERE SALARY > ( SELECT AVG(SALARY) FROM EMPLOYEES WHERE DEPARTMENT = e.DEPARTMENT ) ORDER BY DEPARTMENT;
Output: EMP_ID | EMP_NAME | DEPARTMENT | SALARY -------|---------------|------------|-------- 103 | Amit Patel | IT | 55000 105 | Vikram Desai | IT | 52000
Program 4: PL/SQL Exception Handling
🎯 AIM: To understand and implement PL/SQL exception handling mechanisms including predefined exceptions, user-defined exceptions, and error handling with RAISE statement.
Exception Handling Example 1: Predefined Exceptions
DECLARE v_emp_id NUMBER; v_emp_name VARCHAR2(50); v_salary NUMBER; BEGIN -- This will raise NO_DATA_FOUND exception SELECT EMP_NAME, SALARY INTO v_emp_name, v_salary FROM EMPLOYEES WHERE EMP_ID = 999; DBMS_OUTPUT.PUT_LINE('Employee: ' || v_emp_name); EXCEPTION WHEN NO_DATA_FOUND THEN DBMS_OUTPUT.PUT_LINE('Error: Employee not found!'); WHEN OTHERS THEN DBMS_OUTPUT.PUT_LINE('Error: ' || SQLERRM); END; /
Output: Error: Employee not found! PL/SQL procedure successfully completed.
Exception Handling Example 2: TOO_MANY_ROWS Exception
DECLARE v_dept VARCHAR2(30); v_emp_name VARCHAR2(50); BEGIN SELECT EMP_NAME INTO v_emp_name FROM EMPLOYEES WHERE DEPARTMENT = 'IT'; DBMS_OUTPUT.PUT_LINE('Employee: ' || v_emp_name); EXCEPTION WHEN TOO_MANY_ROWS THEN DBMS_OUTPUT.PUT_LINE('Error: Multiple employees found in IT dept!'); WHEN NO_DATA_FOUND THEN DBMS_OUTPUT.PUT_LINE('Error: No employees found!'); WHEN OTHERS THEN DBMS_OUTPUT.PUT_LINE('Unexpected Error: ' || SQLERRM); END; /
Output: Error: Multiple employees found in IT dept! PL/SQL procedure successfully completed.
Exception Handling Example 3: User-Defined Exception
DECLARE v_emp_id NUMBER := 101; v_salary NUMBER; -- User-defined exception salary_too_high EXCEPTION; BEGIN SELECT SALARY INTO v_salary FROM EMPLOYEES WHERE EMP_ID = v_emp_id; IF v_salary > 52000 THEN RAISE salary_too_high; ELSE DBMS_OUTPUT.PUT_LINE('Salary is acceptable: ' || v_salary); END IF; EXCEPTION WHEN salary_too_high THEN DBMS_OUTPUT.PUT_LINE('Error: Salary exceeds limit of 52000!'); WHEN OTHERS THEN DBMS_OUTPUT.PUT_LINE('Error: ' || SQLERRM); END; /
Output: Salary is acceptable: 50000 PL/SQL procedure successfully completed.
Exception Handling Example 4: PRAGMA EXCEPTION_INIT
DECLARE v_emp_id NUMBER; v_emp_name VARCHAR2(50) := 'John Doe'; -- Associate exception name with Oracle error code duplicate_entry EXCEPTION; PRAGMA EXCEPTION_INIT(duplicate_entry, -00001); BEGIN INSERT INTO EMPLOYEES (EMP_ID, EMP_NAME, DEPARTMENT, SALARY, HIRE_DATE) VALUES (101, v_emp_name, 'IT', 50000, SYSDATE); EXCEPTION WHEN duplicate_entry THEN DBMS_OUTPUT.PUT_LINE('Error: Employee ID already exists!'); WHEN OTHERS THEN DBMS_OUTPUT.PUT_LINE('Error: ' || SQLERRM); END; /
Output: Error: Employee ID already exists! PL/SQL procedure successfully completed.
Exception Handling Example 5: Nested Exception Handling
DECLARE v_emp_id NUMBER; v_emp_name VARCHAR2(50); v_salary NUMBER; BEGIN BEGIN SELECT EMP_NAME, SALARY INTO v_emp_name, v_salary FROM EMPLOYEES WHERE EMP_ID = 102; DBMS_OUTPUT.PUT_LINE('Employee: ' || v_emp_name); DBMS_OUTPUT.PUT_LINE('Salary: ' || v_salary); EXCEPTION WHEN NO_DATA_FOUND THEN DBMS_OUTPUT.PUT_LINE('Inner Exception: Employee not found'); END; DBMS_OUTPUT.PUT_LINE('Processing continues...'); EXCEPTION WHEN OTHERS THEN DBMS_OUTPUT.PUT_LINE('Outer Exception: ' || SQLERRM); END; /
Output: Employee: Priya Singh Salary: 45000 Processing continues... PL/SQL procedure successfully completed.
Program 5: PL/SQL Cursors
🎯 AIM: To understand and implement explicit cursors for row-by-row processing, cursor attributes, and cursor loops.
Cursor Example 1: Implicit Cursor
DECLARE v_rows_updated NUMBER; BEGIN -- Implicit cursor example UPDATE EMPLOYEES SET SALARY = SALARY * 1.10 WHERE DEPARTMENT = 'IT'; -- Use SQL%ROWCOUNT to check affected rows v_rows_updated := SQL%ROWCOUNT; DBMS_OUTPUT.PUT_LINE('Rows updated: ' || v_rows_updated); IF SQL%FOUND THEN DBMS_OUTPUT.PUT_LINE('Update successful'); END IF; ROLLBACK; END; /
Output: Rows updated: 3 Update successful PL/SQL procedure successfully completed.
Cursor Example 2: Explicit Cursor - Basic
DECLARE -- Declare explicit cursor CURSOR emp_cursor IS SELECT EMP_ID, EMP_NAME, SALARY FROM EMPLOYEES WHERE DEPARTMENT = 'IT'; v_emp_id EMPLOYEES.EMP_ID%TYPE; v_emp_name EMPLOYEES.EMP_NAME%TYPE; v_salary EMPLOYEES.SALARY%TYPE; BEGIN DBMS_OUTPUT.PUT_LINE('=== IT Department Employees ==='); -- Open cursor OPEN emp_cursor; -- Fetch records one by one LOOP FETCH emp_cursor INTO v_emp_id, v_emp_name, v_salary; EXIT WHEN emp_cursor%NOTFOUND; DBMS_OUTPUT.PUT_LINE(v_emp_id || ' | ' || v_emp_name || ' | ' || v_salary); END LOOP; -- Close cursor CLOSE emp_cursor; END; /
Output: === IT Department Employees === 101 | Rajesh Kumar | 50000 103 | Amit Patel | 55000 105 | Vikram Desai | 52000 PL/SQL procedure successfully completed.
Cursor Example 3: Cursor FOR Loop
DECLARE CURSOR emp_cursor IS SELECT EMP_ID, EMP_NAME, DEPARTMENT, SALARY FROM EMPLOYEES ORDER BY SALARY DESC; BEGIN DBMS_OUTPUT.PUT_LINE('=== All Employees (Sorted by Salary) ==='); DBMS_OUTPUT.PUT_LINE('ID | Name | Dept | Salary'); DBMS_OUTPUT.PUT_LINE('----+-------------------+----------+-------'); -- FOR loop automatically opens, fetches, and closes cursor FOR emp_rec IN emp_cursor LOOP DBMS_OUTPUT.PUT_LINE( LPAD(emp_rec.EMP_ID, 3) || ' | ' || RPAD(emp_rec.EMP_NAME, 17) || ' | ' || RPAD(emp_rec.DEPARTMENT, 8) || ' | ' || emp_rec.SALARY ); END LOOP; END; /
Output: === All Employees (Sorted by Salary) === ID | Name | Dept | Salary ----+-------------------+----------+------- 103 | Amit Patel | IT | 55000 105 | Vikram Desai | IT | 52000 101 | Rajesh Kumar | IT | 50000 104 | Neha Sharma | Finance | 48000 102 | Priya Singh | HR | 45000 PL/SQL procedure successfully completed.
Cursor Example 4: Parameterized Cursor
DECLARE -- Cursor with parameters CURSOR emp_by_dept_cursor (p_dept VARCHAR2) IS SELECT EMP_ID, EMP_NAME, SALARY FROM EMPLOYEES WHERE DEPARTMENT = p_dept; BEGIN DBMS_OUTPUT.PUT_LINE('=== Employees in HR Department ==='); FOR emp_rec IN emp_by_dept_cursor('HR') LOOP DBMS_OUTPUT.PUT_LINE(emp_rec.EMP_ID || ' - ' || emp_rec.EMP_NAME || ' - Rs.' || emp_rec.SALARY); END LOOP; DBMS_OUTPUT.PUT_LINE(CHR(10) || '=== Employees in Finance Department ==='); FOR emp_rec IN emp_by_dept_cursor('Finance') LOOP DBMS_OUTPUT.PUT_LINE(emp_rec.EMP_ID || ' - ' || emp_rec.EMP_NAME || ' - Rs.' || emp_rec.SALARY); END LOOP; END; /
Output: === Employees in HR Department === 102 - Priya Singh - Rs.45000 === Employees in Finance Department === 104 - Neha Sharma - Rs.48000 PL/SQL procedure successfully completed.
Cursor Example 5: Cursor Attributes
DECLARE CURSOR emp_cursor IS SELECT EMP_ID, EMP_NAME FROM EMPLOYEES; v_count NUMBER := 0; BEGIN OPEN emp_cursor; DBMS_OUTPUT.PUT_LINE('Cursor Attributes Test:'); DBMS_OUTPUT.PUT_LINE('%ISOPEN: ' || CASE WHEN emp_cursor%ISOPEN THEN 'TRUE' ELSE 'FALSE' END); LOOP FETCH emp_cursor INTO v_emp_id, v_emp_name; EXIT WHEN emp_cursor%NOTFOUND; v_count := v_count + 1; END LOOP; DBMS_OUTPUT.PUT_LINE('%ROWCOUNT: ' || emp_cursor%ROWCOUNT || ' rows fetched'); DBMS_OUTPUT.PUT_LINE('%FOUND: ' || CASE WHEN emp_cursor%FOUND THEN 'TRUE' ELSE 'FALSE' END); DBMS_OUTPUT.PUT_LINE('%NOTFOUND: ' || CASE WHEN emp_cursor%NOTFOUND THEN 'TRUE' ELSE 'FALSE' END); CLOSE emp_cursor; DBMS_OUTPUT.PUT_LINE('%ISOPEN after close: ' || CASE WHEN emp_cursor%ISOPEN THEN 'TRUE' ELSE 'FALSE' END); END; /
Output: Cursor Attributes Test: %ISOPEN: TRUE %ROWCOUNT: 5 rows fetched %FOUND: FALSE %NOTFOUND: TRUE %ISOPEN after close: FALSE PL/SQL procedure successfully completed.
Program 6: PL/SQL Triggers
🎯 AIM: To understand and implement PL/SQL triggers for automatic enforcement of business rules and data validation.
Trigger Example 1: BEFORE INSERT Trigger
-- Create SALARY_LOG table CREATE TABLE SALARY_LOG ( LOG_ID NUMBER PRIMARY KEY, OPERATION VARCHAR2(20), EMP_ID NUMBER, OLD_SALARY NUMBER, NEW_SALARY NUMBER, LOG_DATE DATE ); -- Create sequence for LOG_ID CREATE SEQUENCE salary_log_seq START WITH 1; -- Create BEFORE INSERT Trigger CREATE OR REPLACE TRIGGER emp_salary_check BEFORE INSERT ON EMPLOYEES FOR EACH ROW BEGIN -- Validate salary IF :NEW.SALARY < 0 THEN RAISE_APPLICATION_ERROR(-20001, 'Salary cannot be negative!'); END IF; -- Set hire date to current date if NULL IF :NEW.HIRE_DATE IS NULL THEN :NEW.HIRE_DATE := SYSDATE; END IF; DBMS_OUTPUT.PUT_LINE('Before Insert Trigger Fired: New Employee ' || :NEW.EMP_NAME); END emp_salary_check; /
-- Test the trigger BEGIN INSERT INTO EMPLOYEES (EMP_ID, EMP_NAME, DEPARTMENT, SALARY) VALUES (106, 'Suresh Gupta', 'IT', 54000); COMMIT; END; /
Output: Before Insert Trigger Fired: New Employee Suresh Gupta PL/SQL procedure successfully completed.
Trigger Example 2: AFTER INSERT Trigger with Logging
-- Create AFTER INSERT Trigger for logging CREATE OR REPLACE TRIGGER emp_insert_log AFTER INSERT ON EMPLOYEES FOR EACH ROW BEGIN INSERT INTO SALARY_LOG (LOG_ID, OPERATION, EMP_ID, OLD_SALARY, NEW_SALARY, LOG_DATE) VALUES ( salary_log_seq.NEXTVAL, 'INSERT', :NEW.EMP_ID, NULL, :NEW.SALARY, SYSDATE ); DBMS_OUTPUT.PUT_LINE('Log Entry Created for Employee: ' || :NEW.EMP_NAME); END emp_insert_log; /
Output: Log Entry Created for Employee: Suresh Gupta PL/SQL procedure successfully completed.
Trigger Example 3: BEFORE UPDATE Trigger
-- Create BEFORE UPDATE Trigger CREATE OR REPLACE TRIGGER emp_update_validation BEFORE UPDATE ON EMPLOYEES FOR EACH ROW BEGIN -- Prevent salary reduction (salary can only increase or remain same) IF :NEW.SALARY < :OLD.SALARY THEN RAISE_APPLICATION_ERROR(-20002, 'Cannot reduce salary! Old: ' || :OLD.SALARY || ', New: ' || :NEW.SALARY); END IF; -- Validate salary increase (max 20%) IF (:NEW.SALARY - :OLD.SALARY) / :OLD.SALARY > 0.2 THEN RAISE_APPLICATION_ERROR(-20003, 'Salary increase exceeds 20% limit!'); END IF; DBMS_OUTPUT.PUT_LINE('Salary Update Validation Passed for ' || :NEW.EMP_NAME); END emp_update_validation; /
-- Test the update trigger BEGIN UPDATE EMPLOYEES SET SALARY = 55000 WHERE EMP_ID = 101; COMMIT; END; /
Output: Salary Update Validation Passed for Rajesh Kumar PL/SQL procedure successfully completed.
Trigger Example 4: AFTER UPDATE Trigger with Logging
-- Create AFTER UPDATE Trigger CREATE OR REPLACE TRIGGER emp_update_log AFTER UPDATE ON EMPLOYEES FOR EACH ROW BEGIN IF :OLD.SALARY <> :NEW.SALARY THEN INSERT INTO SALARY_LOG (LOG_ID, OPERATION, EMP_ID, OLD_SALARY, NEW_SALARY, LOG_DATE) VALUES ( salary_log_seq.NEXTVAL, 'UPDATE', :OLD.EMP_ID, :OLD.SALARY, :NEW.SALARY, SYSDATE ); DBMS_OUTPUT.PUT_LINE('Salary Update Logged: ' || :OLD.SALARY || ' -> ' || :NEW.SALARY); END IF; END emp_update_log; /
Output: Salary Update Logged: 50000 -> 55000 PL/SQL procedure successfully completed.
Trigger Example 5: BEFORE DELETE Trigger
-- Create BEFORE DELETE Trigger CREATE OR REPLACE TRIGGER emp_delete_protection BEFORE DELETE ON EMPLOYEES FOR EACH ROW BEGIN -- Check if employee has active projects IF EXISTS ( SELECT 1 FROM PROJECTS WHERE EMP_ID = :OLD.EMP_ID ) THEN RAISE_APPLICATION_ERROR(-20004, 'Cannot delete employee with active projects!'); END IF; DBMS_OUTPUT.PUT_LINE('Employee ' || :OLD.EMP_NAME || ' cleared for deletion'); END emp_delete_protection; /
Output: Employee will be deleted after this check PL/SQL procedure successfully completed.

Program 7: PL/SQL Packages
🎯 AIM: To understand and implement PL/SQL packages with specification and body for modular programming and code reusability.
Package Example: Employee Management Package
Step 1: Create Package Specification
CREATE OR REPLACE PACKAGE emp_mgmt_pkg AS -- Package-level variables/constants max_salary_increase CONSTANT NUMBER := 0.20; -- Procedure to add new employee PROCEDURE add_employee ( p_emp_id IN EMPLOYEES.EMP_ID%TYPE, p_emp_name IN EMPLOYEES.EMP_NAME%TYPE, p_dept IN EMPLOYEES.DEPARTMENT%TYPE, p_salary IN EMPLOYEES.SALARY%TYPE ); -- Procedure to update salary PROCEDURE update_salary ( p_emp_id IN EMPLOYEES.EMP_ID%TYPE, p_new_salary IN EMPLOYEES.SALARY%TYPE ); -- Function to get employee details FUNCTION get_emp_salary ( p_emp_id IN EMPLOYEES.EMP_ID%TYPE ) RETURN EMPLOYEES.SALARY%TYPE; -- Function to calculate bonus FUNCTION calculate_bonus ( p_emp_id IN EMPLOYEES.EMP_ID%TYPE, p_percentage IN NUMBER ) RETURN NUMBER; -- Procedure to get department statistics PROCEDURE get_dept_stats ( p_dept IN EMPLOYEES.DEPARTMENT%TYPE, p_avg_salary OUT NUMBER, p_emp_count OUT NUMBER ); END emp_mgmt_pkg; /
Step 2: Create Package Body
CREATE OR REPLACE PACKAGE BODY emp_mgmt_pkg AS -- Implementation of add_employee procedure PROCEDURE add_employee ( p_emp_id IN EMPLOYEES.EMP_ID%TYPE, p_emp_name IN EMPLOYEES.EMP_NAME%TYPE, p_dept IN EMPLOYEES.DEPARTMENT%TYPE, p_salary IN EMPLOYEES.SALARY%TYPE ) AS BEGIN IF p_salary < 0 THEN RAISE_APPLICATION_ERROR(-20001, 'Salary cannot be negative'); END IF; INSERT INTO EMPLOYEES (EMP_ID, EMP_NAME, DEPARTMENT, SALARY, HIRE_DATE) VALUES (p_emp_id, p_emp_name, p_dept, p_salary, SYSDATE); DBMS_OUTPUT.PUT_LINE('Employee ' || p_emp_name || ' added successfully'); COMMIT; END add_employee; -- Implementation of update_salary procedure PROCEDURE update_salary ( p_emp_id IN EMPLOYEES.EMP_ID%TYPE, p_new_salary IN EMPLOYEES.SALARY%TYPE ) AS v_old_salary EMPLOYEES.SALARY%TYPE; v_emp_name EMPLOYEES.EMP_NAME%TYPE; BEGIN SELECT SALARY, EMP_NAME INTO v_old_salary, v_emp_name FROM EMPLOYEES WHERE EMP_ID = p_emp_id; IF p_new_salary < v_old_salary THEN RAISE_APPLICATION_ERROR(-20002, 'Cannot reduce salary'); END IF; IF (p_new_salary - v_old_salary) / v_old_salary > max_salary_increase THEN RAISE_APPLICATION_ERROR(-20003, 'Salary increase exceeds limit'); END IF; UPDATE EMPLOYEES SET SALARY = p_new_salary WHERE EMP_ID = p_emp_id; DBMS_OUTPUT.PUT_LINE('Salary updated for ' || v_emp_name); COMMIT; END update_salary; -- Implementation of get_emp_salary function FUNCTION get_emp_salary ( p_emp_id IN EMPLOYEES.EMP_ID%TYPE ) RETURN EMPLOYEES.SALARY%TYPE AS v_salary EMPLOYEES.SALARY%TYPE; BEGIN SELECT SALARY INTO v_salary FROM EMPLOYEES WHERE EMP_ID = p_emp_id; RETURN v_salary; EXCEPTION WHEN NO_DATA_FOUND THEN RAISE_APPLICATION_ERROR(-20004, 'Employee not found'); END get_emp_salary; -- Implementation of calculate_bonus function FUNCTION calculate_bonus ( p_emp_id IN EMPLOYEES.EMP_ID%TYPE, p_percentage IN NUMBER ) RETURN NUMBER AS v_salary EMPLOYEES.SALARY%TYPE; BEGIN v_salary := get_emp_salary(p_emp_id); RETURN v_salary * (p_percentage / 100); END calculate_bonus; -- Implementation of get_dept_stats procedure PROCEDURE get_dept_stats ( p_dept IN EMPLOYEES.DEPARTMENT%TYPE, p_avg_salary OUT NUMBER, p_emp_count OUT NUMBER ) AS BEGIN SELECT AVG(SALARY), COUNT(*) INTO p_avg_salary, p_emp_count FROM EMPLOYEES WHERE DEPARTMENT = p_dept; EXCEPTION WHEN NO_DATA_FOUND THEN p_avg_salary := 0; p_emp_count := 0; END get_dept_stats; END emp_mgmt_pkg; /
Step 3: Use the Package
DECLARE v_avg_salary NUMBER; v_emp_count NUMBER; v_bonus NUMBER; BEGIN DBMS_OUTPUT.PUT_LINE('=== Employee Management Package Demo ==='); DBMS_OUTPUT.PUT_LINE(CHR(10)); -- Add new employee emp_mgmt_pkg.add_employee(107, 'Pooja Verma', 'IT', 56000); -- Get employee salary DBMS_OUTPUT.PUT_LINE('Employee ID 107 Salary: ' || emp_mgmt_pkg.get_emp_salary(107)); -- Calculate bonus v_bonus := emp_mgmt_pkg.calculate_bonus(107, 10); DBMS_OUTPUT.PUT_LINE('10% Bonus: ' || v_bonus); -- Get department statistics emp_mgmt_pkg.get_dept_stats('IT', v_avg_salary, v_emp_count); DBMS_OUTPUT.PUT_LINE(CHR(10) || 'IT Department Stats:'); DBMS_OUTPUT.PUT_LINE('Average Salary: ' || ROUND(v_avg_salary, 2)); DBMS_OUTPUT.PUT_LINE('Employee Count: ' || v_emp_count); END; /
Output: === Employee Management Package Demo === Employee Pooja Verma added successfully Employee ID 107 Salary: 56000 10% Bonus: 5600 IT Department Stats: Average Salary: 53666.67 Employee Count: 4 PL/SQL procedure successfully completed.

CREATE OR REPLACE PACKAGE BODY library_pkg AS PROCEDURE issue_book ( p_member_id IN NUMBER, p_book_id IN NUMBER, p_transaction_id OUT NUMBER ) AS v_available NUMBER; v_trans_id NUMBER; BEGIN -- Check book availability SELECT AVAILABLE_COPIES INTO v_available FROM BOOKS WHERE BOOK_ID = p_book_id; IF v_available <= 0 THEN RAISE_APPLICATION_ERROR(-20001, 'Book not available!'); END IF; -- Get new transaction ID SELECT NVL(MAX(TRANSACTION_ID), 5000) + 1 INTO v_trans_id FROM ISSUE_RETURN; -- Insert issue record INSERT INTO ISSUE_RETURN (TRANSACTION_ID, MEMBER_ID, BOOK_ID, ISSUE_DATE, DUE_DATE, FINE_AMOUNT) VALUES (v_trans_id, p_member_id, p_book_id, SYSDATE, SYSDATE + 14, 0); -- Update available copies UPDATE BOOKS SET AVAILABLE_COPIES = AVAILABLE_COPIES - 1 WHERE BOOK_ID = p_book_id; p_transaction_id := v_trans_id; DBMS_OUTPUT.PUT_LINE('Book issued successfully! Transaction ID: ' || v_trans_id); COMMIT; EXCEPTION WHEN OTHERS THEN RAISE_APPLICATION_ERROR(-20099, SQLERRM); END issue_book; PROCEDURE return_book ( p_transaction_id IN NUMBER, p_return_date IN DATE ) AS v_due_date DATE; v_book_id NUMBER; v_fine NUMBER; BEGIN SELECT DUE_DATE, BOOK_ID INTO v_due_date, v_book_id FROM ISSUE_RETURN WHERE TRANSACTION_ID = p_transaction_id; -- Calculate fine if overdue v_fine := calculate_fine(v_due_date, p_return_date); -- Update return record UPDATE ISSUE_RETURN SET RETURN_DATE = p_return_date, FINE_AMOUNT = v_fine WHERE TRANSACTION_ID = p_transaction_id; -- Update available copies UPDATE BOOKS SET AVAILABLE_COPIES = AVAILABLE_COPIES + 1 WHERE BOOK_ID = v_book_id; DBMS_OUTPUT.PUT_LINE('Book returned successfully! Fine: Rs.' || v_fine); COMMIT; EXCEPTION WHEN OTHERS THEN RAISE_APPLICATION_ERROR(-20099, SQLERRM); END return_book; FUNCTION calculate_fine ( p_due_date IN DATE, p_return_date IN DATE ) RETURN NUMBER AS v_days_late NUMBER; v_fine NUMBER := 0; BEGIN v_days_late := p_return_date - p_due_date; IF v_days_late > 0 THEN v_fine := v_days_late * 10; -- Rs. 10 per day END IF; RETURN v_fine; END calculate_fine; PROCEDURE get_member_books ( p_member_id IN NUMBER ) AS CURSOR book_cursor IS SELECT i.TRANSACTION_ID, b.TITLE, i.ISSUE_DATE, i.DUE_DATE, i.RETURN_DATE FROM ISSUE_RETURN i JOIN BOOKS b ON i.BOOK_ID = b.BOOK_ID WHERE i.MEMBER_ID = p_member_id; BEGIN DBMS_OUTPUT.PUT_LINE('Books issued to Member ID: ' || p_member_id); DBMS_OUTPUT.PUT_LINE('---------------------------------------------'); FOR book_rec IN book_cursor LOOP DBMS_OUTPUT.PUT_LINE( 'Trans ID: ' || book_rec.TRANSACTION_ID || ' | Book: ' || book_rec.TITLE || ' | Due: ' || TO_CHAR(book_rec.DUE_DATE, 'DD-MON-YYYY') ); END LOOP; END get_member_books; PROCEDURE get_overdue_books AS CURSOR overdue_cursor IS SELECT i.TRANSACTION_ID, m.MEMBER_NAME, b.TITLE, i.DUE_DATE, i.RETURN_DATE FROM ISSUE_RETURN i JOIN MEMBERS m ON i.MEMBER_ID = m.MEMBER_ID JOIN BOOKS b ON i.BOOK_ID = b.BOOK_ID WHERE i.RETURN_DATE IS NULL AND i.DUE_DATE < SYSDATE; BEGIN DBMS_OUTPUT.PUT_LINE('=== OVERDUE BOOKS ==='); FOR overdue_rec IN overdue_cursor LOOP DBMS_OUTPUT.PUT_LINE( overdue_rec.MEMBER_NAME || ' | ' || overdue_rec.TITLE || ' | Days Late: ' || (SYSDATE - overdue_rec.DUE_DATE) ); END LOOP; END get_overdue_books; FUNCTION get_available_copies ( p_book_id IN NUMBER ) RETURN NUMBER AS v_available NUMBER; BEGIN SELECT AVAILABLE_COPIES INTO v_available FROM BOOKS WHERE BOOK_ID = p_book_id; RETURN v_available; EXCEPTION WHEN OTHERS THEN RETURN -1; END get_available_copies; END library_pkg; /

  • Clear Output: Use Clear Output button to clean the output pane
  • Format Code: Press Ctrl+Shift+F to auto-format SQL code
Common Errors & Solutions
❌ ORA-00001: unique constraint violated
Solution: You're trying to insert a duplicate primary key. Check existing data or use different ID.
❌ ORA-01403: no data found
Solution: SELECT INTO query returned no rows. Add exception handling or verify data exists.
❌ ORA-01422: exact fetch returns more than requested number of rows
Solution: SELECT INTO returned multiple rows. Use cursor or LIMIT to fetch one row.
❌ ORA-00942: table or view does not exist
Solution: Table not created or wrong table name. Create table before using it.
❌ PL/SQL: compilation error
Solution: Check syntax errors. Look at error line number and verify brackets, semicolons, keywords.
Best Practices
✓ Use %TYPE and %ROWTYPE
For variable declarations, use table column types to ensure compatibility:
v_emp_id EMPLOYEES.EMP_ID%TYPE;
✓ Always include Exception Handling
Wrap code in BEGIN-EXCEPTION-END blocks to handle errors gracefully.
✓ Use Comments
Use -- for single-line and /* */ for multi-line comments to document code.
✓ Commit Regularly
Use COMMIT after successful DML operations to save changes permanently.
✓ Use Meaningful Names
Name variables, procedures, and functions clearly: v_ for variables, p_ for parameters.
